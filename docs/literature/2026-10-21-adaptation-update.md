# Adaptation literature and a bounded contribution for the deadline

Independent evidence-review notes. Where proposed sample counts differ, the controlling proposal is [publication-plan.md](../research/2026-10-21-publication-plan.md); the only ready VM work is [GSFM-003](../experiments/GSFM-003.md). This note does not authorize its longer training suggestion.

Read 21 October 2026. Full HTML/PDF sections were inspected for the papers below, rather than relying only on abstracts. Numerical findings below are authors' reports, not our reproductions. This is a focused novelty search, not a proof that no prior work exists. The current VM results and operator diagnosis were supplied by the parent task; I did not independently rerun them.

## Decision

The strongest plausible short-paper question is **whether a released surrogate's numerically regularized training physics biases adaptation on a standard benchmark, and whether restoring the target's exact physical equations improves held-out AC-OPF predictions at a fixed adaptation budget**. The distinctive ingredient is the specific causal mechanism: an AC-OPF reference which is feasible under the target network is penalized by the released v1.1 clamped operator. This is narrower than saying GridSFM is inaccurate, physics losses help, or LoRA makes adaptation efficient: all three have close prior art.

The current evidence is a diagnostic, not an established novel method or demonstrated improvement. A one-line clamp fix on one case may be too slight for a paper unless it produces a generalizable measurement protocol, analytically explained effect and controlled adaptation results. Do not promise acceptance. Pin the Microsoft v1.1 code and checkpoint; do not frame its behavior as all current GridSFM implementations.

## At most three promising questions, ranked

1. **Does numerical regularization in the released training operator bias target-grid adaptation?** Show the feasible-reference residual under exact and stock operators, the affected branches, epsilon sensitivity, and gradients near the same reference. Then compare frozen, no-KCL FT, stock-KCL FT and exact-KCL FT. Retain all other loss terms identically; no-KCL is an ablation of this term, not removal of all other physics losses. Same checkpoint, scenario splits, optimizer budget, data terms and KCL weighting/normalization. Avoid accidentally changing other terms through a shared helper. Evaluate all predictions with original network equations. The principal claim is empirical and version-specific. Merely reducing the internal training loss is not success.
2. **Does the answer depend on adaptation capacity?** If the first comparison gives a stable signal, repeat stock/exact physics under one predeclared FFN-LoRA rank, plus matched full FT. This is a compact interaction test: does correcting the equations help a restricted adapter as much as full adaptation? It is stronger than an isolated “LoRA works” demonstration, but secondary so it cannot consume the deadline. A head-only comparator is useful if near-free, since close prior work finds simple partial adaptation competitive.
3. **How far does the observed mechanism generalize across standard networks?** Audit exact-reference/stock-operator discrepancies on case39, case118, case300 and one shipped supported 500-bus control, using a few feasible points each. Do not train all four or connect five case300s. If effect is unique to case300, explicitly present it as a benchmark/release-specific finding. If multiple standard cases contain affected impedances, one second training case strengthens the result more than another two-copy graph.

## Small executable pilot before committing to a paper claim

Use original MATPOWER case300 as the main target. Generate 100 training, 50 validation and 100 untouched test feasible AC-OPF points, keeping failed attempts in the manifest rather than relabeling them infeasible. This is a proposed budget, to adjust to measured VM throughput. Vary individual loads as well as overall demand; five global multipliers alone form an inadequate training/test study. Keep costs, line parameters and topology fixed in the pilot so the intervention is interpretable. Reuse the same reference set for every method. Audit case39 as a candidate operator negative control (confirm whether any branches cross the clamp threshold before labeling it so), and audit the shipped supported samples without committing to additional training; connected case300x2 remains optional.

Initially run one seed and a short fixed update cap for no-KCL, stock-KCL, exact-KCL full FT. Match precision in the operator comparison; if exact physics needs float64, also give stock physics float64 so precision is not a confound. Use gradient clipping of optimization gradients if needed, not modification of the physical parameters. Confirm a backward pass and finite gradients before longer runs. Select by a predeclared validation criterion using independently recomputed physical residuals, not the method's own potentially distorted physics loss.

Complete three training seeds for the primary 100-label comparison once the short pilot is technically stable. Only if there is a clear repeatable benefit: add a second training-data budget (e.g. 50 versus 100 labels); add FFN-LoRA under the same operators if implementation is stable. Report case-wise paired differences and across-seed spread, voltage/dispatch errors, exact maximum and tail P/Q imbalance, generator/voltage violations, cost error and all-constraint pass fraction with explicit tolerances. Original MATPOWER case300 RATE_A=0 throughout: no original interior thermal-overload conclusions are available. A separate rated PGLib case300 is a different problem and must be named as such.

The inspected loss.py is on the released fine-tuning path; its presence is not evidence that original pretraining used that exact implementation. Training loss physics is not used to update frozen inference outputs, so fixing it does not itself explain or cure the already observed zero-shot error. The causal hypothesis concerns **subsequent adaptation**, with no claim of first use or original pretraining causality. If stock/exact FT perform similarly or both fail, that falsifies the hoped-for improvement; it must not be hidden or recast as an efficiency success. A systematic reproducibility finding may remain useful, but publication strength must then be reassessed rather than assumed.

Do not spend the deadline on a new architecture, extensive hyperparameter sweeps, full CSP reimplementation, five connected case300s, or solver speedup when the present warm-start evidence is negative. Acknowledge newer GridSFM completion work; if quick to run, a frozen newer-release reference is a useful contextual control, otherwise transparently bound the scope to v1.1 rather than implying state of the art.
