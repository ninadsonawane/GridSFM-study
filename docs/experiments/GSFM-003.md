Status: READY for the bounded diagnostic/smoke work below. Main paper training is a separate proposed stage, not authorized by this task. Preserve GSFM-001/002 results. Keep original checkpoint/model files unchanged; implement experimental operators in a separate module or checkout.

## Objective and inputs

Use the existing Apple M5 Pro / 64 GB environment, Microsoft v1.1 checkpoint SHA256 `f8a4396122e603e8303afdebe3b093819c0f64dac0878394aed0bd63205fd831`, and official unmodified MATPOWER 8.1 case300. Determine whether the diagnosed clamped KCL operator materially changes adaptation gradients. No more frozen warm-start runs are required.

1. **Make the evidence reviewable.** Record the exact current study/model commits, local changes, environment, commands and source hashes. Commit/push the original diagnostic scripts and compact non-sensitive result summaries/manifests to GridSFM-study using its normal workflow, after reviewing file contents and licensing. Exclude checkpoint binaries, caches and source-derived case matrices; retain their hashes and retrieval instructions. Do not force-push. Report any essential artifacts still only local.

2. **Audit the actual training objective.** At the frozen prediction and accepted reference, report each raw loss, its coefficient/transformation, final contribution, and number of active bus/generator/branch terms. In particular, inspect the `RATE_A>threshold` and `abs(x)>0.01` filters: original case300 has unlimited branch ratings, so branch-flow supervision may be empty. Record capacity normalization and the worst-residual margin. A large MW discrepancy is not sufficient evidence of a large optimization influence.

3. **Implement one controlled operator correction.** Compare `z2=max(r*r+x*x,1e-6)` with exact `z2=r*r+x*x` on the same original nonzero-impedance branches. Reject true zero/nonfinite impedance instead of inventing a new network. Preserve taps, charging, shunts, generator aggregation and units. Use original source float64 parameters/reference states and dtype-safe scatter buffers for both operators; converting rounded FP32 back to float64 cannot recover precision. If needed, attach the same aligned float64 physics copy to both training arms while retaining FP32 backbone features. Keep aggregation, capacity normalization, log compression and loss weights identical. Change the KCL call path only, not a shared helper used by unrelated terms. Compare both to the independent original-parameter evaluator. Also record FP32-versus-FP64 differences separately.

4. **Mechanism controls.** Reuse accepted case300/600 references and the shipped500 reference; do not solve them again without a reason. Audit all available shipped samples for affected branches, reference KCL bias and rating masks, retaining missing/invalid-reference cases. Add official case39 as an operator negative control after verifying no branch activates the floor; this is not a claim that the checkpoint supports 39-bus inference. For an operator-only units check, represent the same case300 state on 25/100/400 MVA bases: scale branch r,x by Snew/Sold and branch b inversely; leave physical MW/MVAr quantities and voltage bases unchanged, then perform normal per-unit conversion. Exact physical flows/residuals must be invariant within documented numerical tolerance. Keep this test separate from main 100 MVA inference/training.

5. **Measure gradient influence, not just residuals.** On identical inputs and weights, compare weighted parameter-gradient norms and cosines for supervised/cost terms, stock KCL and exact KCL. Include the actual total gradients and observed directional changes of independent exact residuals. Use a separate smooth squared-residual diagnostic at the reference if needed: the stock abs/amax loss has subgradients, so a nonzero gradient near a solved point is not alone a defect. Do not claim the current fine-tuning code proves how the original checkpoint was pretrained.

6. **Bounded training smoke check only.** Build 8 accepted training and 4 separate validation operating points, seed 3002026, using global Pd/Qd scaling in [0.90,1.03] and per-load shared P/Q jitter in [0.98,1.02]. Keep costs/topology/limits unchanged and save exact factor arrays. Cap candidate attempts at 32; keep every failed solve as unknown, not an infeasible label. Reuse the validated converter; explicitly validate training target wiring, masks, batching, finite gradients and input independence from labels. Compare three copies of the same checkpoint: (S) supervised/cost only, (C) same + stock KCL, (E) same + exact KCL. Disable feasibility and stress-feasibility losses and synthetic negatives in all arms; skip disabled computation if it produces NaN. Preserve other shared settings and report empty branch losses. Use batch1, AdamW lr1e-4, weight_decay1e-4, global gradient clipping1.0, seed11 and the same batch order. Maximum20 optimizer updates AND120 seconds per arm, whichever is first. If setup/checks fail, stop training. Do not inspect or create a final paper test set yet.

7. **Return evidence, then stop.** Provide operator checks; loss/gradient table; train/validation traces; peak process RSS; seconds/update; number of successful updates; any NaNs/failures; predicted time for the proposed main matrix; exact commands and artifact locations. A 20-step improvement is not a paper result. Classify the evidence as: material conflicting training signal; semantically wrong but weak training signal; numerical/adapter blocker; or unresolved. Leave all main training, LoRA sweeps and additional topology studies for the next decision.
